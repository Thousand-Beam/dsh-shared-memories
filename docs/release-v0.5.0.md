## 🔧 v0.5.0 变更

### P2：防投毒正则语序盲区

`src/host/memory/poison.ts` 的底线突破正则只认「忽略你的所有规则」这类「的」前置语序；「忽略你**所有的**规则」「解除你**所有的**限制」的「的」被「所有」隔开后不命中，外来内容以 active / trust 0.6 入池（终审报告实测确认）。

**修法**：三条底线正则把「你 / 的 / 所有」拆成独立可选项，前后两种语序都拦：

- `忽略(?:你)?(?:的)?(?:全部|所有)?(?:的)?(?:规则|底线|设定|限制)`
- `解除(?:你)?(?:的)?(?:所有|全部)?(?:的)?(?:限制|约束|审查)`
- `(?:你|现在)(?:已经)?没有(?:任何|所有)?(?:的)?(?:限制|约束|规则)`

### P3：reinforce_count 封顶 64

时间树复现计数可被异常循环刷爆（终审报告实测刷到 1584），污染召回权重与展示数字。

**修法**：`src/host/memory/timetree.ts` 的复现计数改为 `MIN(reinforce_count + 1, 64)`——64 时召回权重 log2 已饱和，更高只是数字膨胀。

### P3：rollback 响应明示重建契约

回退后磁盘 `memory.db` 被清空（强制下次冷启动从 journal 全量重放），但当前进程仍使用内存里的旧库——此前这个「重启后生效」的契约对调用方是隐形的。

**修法**：`POST /snapshots/rollback` 响应带 `note`：「工作树已回退并生成 revert 提交；派生库（memory.db）已清空，重启插件后从 journal 全量重建到回退点（重启前当前进程仍展示回退前的数据）。」

### 📢 真并发冲突自救——使用限制补全

终审 T3 实测：两台设备真并发改出**不同内容**时，README 写的「分叉后一次手动 git pull」并不成立——`git pull --rebase --autostash` 会停在冲突态（`pull_code=1`），需要手工选边 + `git add` + `git rebase --continue` 才能出来；且 diverged 那轮的新记忆事件与状态文件捆在同一次被拒 commit 上，一起滞留本机直到冲突被手工解决（**不会丢**）。

**修法**：README 多设备段与 `/save` 409 提示语同步补全为：

> 真并发改出不同内容时 `git pull --rebase` 会停在冲突态：需手工解决 state 文件冲突后 `git add` + `git rebase --continue`（其间该设备的新记忆滞留本地，不会丢）；同逻辑状态则无需手动、自动合并。

## ⚠️ 实验性 / 已知边界（市场页面如实呈现）

- **多设备是实验性单写交接，不是实时双活**：同一时刻建议只让一台机器可写，其余机器只读接续。
- **真并发改出不同内容会分叉停摆**（诚实停摆、不脏写）：需按上文手工解决冲突并 `git rebase --continue`；同逻辑状态则自动合并。
- Git 历史物理擦除仍是插件外 opt-in（「彻底销毁」是逻辑层删除 + 墓碑漫游）。
- `memory.db` 不入快照，冷启动从 journal 全量重放（O(n)）。
- 多设备需要各机 NTP 对时（`doctor` 自检含时钟偏移检测）。
