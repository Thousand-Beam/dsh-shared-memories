# 共享记忆 · Shared Memories `v0.5.4`

这一版修掉两个问题：一个真机 bug（快照之后只要写过东西，下次重启就误判「快照损坏」并整机降级只读），一个终审报告第七章建议的收尾项（分叉时把「最近一次共同祖先快照」一并返回）。

## 🔧 v0.5.4 变更

### 快照校验改读 git 对象，重启不再误判降级（P0 真机 bug）

旧逻辑拿「工作区文件」逐字节对比快照清单的 sha256。工作区在快照之后会继续写（journal 追加、状态文件重写、purge 删行），文件必然对不上，于是「快照之后写过东西的机器，下次重启一律判 snapshot-corrupt 并整机只读」——和「无感换机」正好相反。

现在校验基准改成 `snap/<id>` tag 指向的提交里的内容：

- 快照之后的正常写入不再参与校验；
- 远端投毒、历史被改写、坏提交仍然能被抓出来；
- `git fetch` 补 `--tags`：新设备初始化后本地没有 snap tag，不补这条冷启动一律 snapshot-file-missing；
- 0 字节截断仍会从 git HEAD 自愈（重放读的是工作区文件，截断必须救）。

两条篡改测试（单元 + 自检）同步改成「改内容 → commit --amend → 重写 tag」模拟真实投毒。

### /save 分叉响应附最近共同祖先快照 id（终审第七章第 3 件）

推送发生分叉时，409 响应的 data 现在带 `baseSnapshotId`——`git merge-base` 求共同祖先后 `git describe --match 'snap/*'` 找最近快照。前端提示变成：

> 快照已本地保存，但未推送到远端：diverged（最近共同祖先快照：20260115T030000Z-devA）

方便在冲突时定位「从哪一版分出去的」。
