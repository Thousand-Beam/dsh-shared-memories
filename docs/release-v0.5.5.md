# dsh-shared-memories v0.5.5

会话删了，重启又回来了。这一版才算把它送走。

上周有人点「彻底销毁」，绿条跳出来，说得明明白白：「已销毁 0 条记忆、0 个版本、2 份会话日志；侧栏那一行已删除」。行也确实没了。

然后重启。

它回来了。

数据是 0，记忆是 0，但那行顶在那儿，点开还是个空壳。删了个寂寞。

翻源码，破案了。宿主的工作区有个很绅士的设计：归档，不摘号。你把会话归档，它把 id 从列表里藏起来，但牌子还挂在墙上——这样你哪天反悔点「取消归档」，它还能回到原来的位置，不挪窝。

绅士归绅士，跟「彻底销毁」放一块就别扭：我们的销毁只清了数据和日志，没去摘那块牌子。宿主一重启，拿着牌子满院子找，照片没有，门口还是多出一行。

所以最后一刀补在牌子上：调宿主自己的 `workspaceRegistry.detachSession()`，把会话 id 从记账里真·摘掉。走宿主的 API，不撬 workspace.json 的锁——上次撬锁撬出过「未分组」「未命名」俩幽灵，挨过打，长记性。

测试 160/160，self-test 57/57，另外加了两条回归盯着这一脚：摘没摘、宿主没这服务时会不会自己摔。

验证方法就一句：重启 DSH，随手删个会话，再重启。它要是还能回来，那我信它能自己写周报。
