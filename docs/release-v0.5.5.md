## v0.5.5

修了一个「删不掉」的 bug：会话点「彻底销毁」之后，重启 DSH 又回来了。

定位下来，销毁其实清得挺干净——记忆库、journal、宿主的会话日志目录都删了。问题出在宿主的 workspace 记账：归档一个会话时，它只是把 id 藏起来，槽位还留着（这是为了「取消归档」时能回到原来的位置）。所以我们这边归档完，id 还挂在记账里，宿主重启一扫，空壳行又长回来了。

这版在销毁流程最后加了一步：调宿主的 `workspaceRegistry.detachSession()`，把 id 从记账里摘掉。幂等，走宿主自己的 API，不直接改磁盘上的 workspace.json。

测试 160/160，self-test 57/57，新增两条回归。
