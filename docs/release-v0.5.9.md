# v0.5.9

一台新设备装好插件，第一次开起来就是红条：**「恢复未就绪（degraded），拒绝写入操作」**。重启几次都一样，什么都存不进去。这一版修的就是它。

**现象**

面板上写着「快照提交里缺少文件：journal/devices/QS-DT/2026-11-22.jsonl」。意思很直白：快照的清单里说有这份文件，但那个快照的提交里没有。

**为什么**

快照分两步：先扫工作区，把每个文件的名字和 sha256 列成清单；再 `git add -A` 把它们提交上去。

问题是这两步之间，工作区还在动——journal 会新建当天的文件，也可能有文件刚好被删掉、或者被某条忽略规则挡住。于是清单里多记了一条，提交里却没有。之前没人在意这个差值，直到 v0.5.4 把启动校验从「比工作区文件」改成「比快照提交里的内容」：清单里多出来那一条，现在会被判成快照缺文件，整机降级只读。

严格本身没错，错在清单和提交本来就不该有差值。

**怎么修的**

- **写快照时**，提交前先拿 `git ls-files` 对一遍索引，清单里没进提交的条目直接剔掉并告警。清单从此只描述「提交里真有的东西」。
- **启动校验时**，遇到旧版本留下的坏清单不再一刀切降级：如果那个文件在工作区里、内容和清单哈希对得上，说明数据本身没坏，只是快照副本缺一份——放行、告警，提示你保存一次新快照补齐。内容被换过的真篡改，哈希对不上，照样降级。

第二条是为了让已经中招的机器能直接活过来，不用手改 git 历史。

**验证**

装上来重启，红条应该没了，面板回到可写。启动日志里如果出现「清单多列了……」的告警，说明用的还是旧快照，随手保存一次就好。

测试 164/164，self-test 57/57。
