# v0.6.0

终审把 v0.5.9 拦下来了，理由充分：多设备场景有三个会真出事的问题，加上几个发布层面的毛病。这一版把第一批和第二批要求全修完，重新送审。

## 修了什么

**切换 Agent 后面板卡死。** 之前切到另一个 Agent，面板永远停在「正在冷启动恢复」，只能刷新页面。原因是切过去之后把加载状态置上了，但数据回来之后没人把它复位。现在数据一到就复位，出错也复位并给出提示。

**无痕会话被工具击穿。** 蒸馏、建会话、停机那几处都知道无痕会话不能写记忆，唯独模型直接调 `memory_remember` 这条链路漏了。实测无痕会话里工具调用成功落库。现在工具链自己带一道闸门：无痕会话名下直接拒写，库里一行不留。

**一键回退后重启必降级。** 回退会生成一个 revert 提交，但它从来不推给远端。下次启动 `pull` 一看本地领先远端，ff-only 直接失败，整机只读。现在回退提交会主动推送，走和快照相同的推送上限闸门；真推不上去也不假装成功，明确告诉你远端还停在回退前。

**两台设备的快照互相剪除。** 这是多设备场景最重的伤：每台设备拍快照时 `git add -A` 会把「本机磁盘上不存在的外设备快照清单」暂存成删除，推上去之后就把对方的账本抹了。评审实测 dev-A 的一次提交删了 dev-B 清单 42 行。修了四件事：

1. 清理快照只清理本机的，不再碰别的设备的目录和 tag；
2. 提交时把外设备账本从暂存区恢复成原状——本机提交永远不含「删除他机文件」的变更；
3. 本机清单只列本机条目（state 也按设备分目录），外设备文件完整性由对方自己负责，谁也不再替谁背书；
4. 恢复未就绪期间自动快照本来就跳过，这次确认并保留。

**真分叉测试在 CI 上失败。** 上一版发布时 164 个测试里唯一失败的那个，是测试自己搭错了：A 连拍两次快照但两次内容完全一样，B 的改动和 A 没有共同文件冲突，git 自然干净合并，`pushed` 为 true，断言失败。评审说得对，这是测试搭建缺陷，不是引擎错误。现在 A 第二次快照真改了人格，真分叉终于造得出来，断言成立。

**防投毒三个新绕过。** 全角英文（不归一化就漏）、中文「忘记」系列动词、修饰词穿插（"ignore all of your previous rules"）。三个向量都实测能写入记忆池，这次全堵上，各钉一条测试。

**导入两条链路。** 不带 format 的 JSON 导入会走 Markdown 原文入库；带 BOM 的 JSON 直接报错。两条都修了，自动识别和显式格式各加测试。

**推送出闸门。** 推送重试最坏要两分钟，之前整段包在写闸门里，网络抖动期间所有记忆写入全部挂起。现在推送在闸门外执行。另外分叉判定收紧：只有 rebase 因内容冲突失败才算分叉停摆，瞬时网络错误按可重试失败处理，不再把用户误导向「历史分叉」。Pin 清单读不出来时也不清理任何快照（宁可少删，不可误删）。
